## Phase 3 — Spatial Index and Benchmark
- Requirements: R2.3, K4, P2, A2; decisions D-06 and D-11. Java 25 retained; `zone-core` compile dependencies remain empty.
- Status: complete; implementation, benchmark execution, acceptance verification, and independent source/diff review complete. Phase 4 was not started.
- Implementation: added immutable zone metadata, snapshots/build statistics, independent naive exact-scan index, and STR-packed R-tree using private flat primitive node/zone-envelope arrays and ordinal references. Tree queries use iterative traversal and a shared per-thread reusable stack; nested callback reentrancy takes a temporary stack. Added deterministic synthetic zone/point generators, JMH point/build/candidate benchmarks, candidate distribution report, runtime heap sweep, and an open-loop 50k qps harness.
- Correctness: R-tree and naive queries compare complete ordered `ZoneHit` values across 50 fixed-seed scenarios × 100,000 points each, capacities 4/16/64, plus concave/hole/negative/identical-bbox/touching/empty/single fixtures. Candidate retrieval has a separate expanded-bbox oracle test. Sixteen concurrent readers and callback reentrancy are covered.
- Benchmark environment: Apple M2, 8 CPU cores (4 performance + 4 efficiency), 16 GB RAM, macOS 26.5.1, OpenJDK 25.0.2. Dataset seeds, extents, sizes, JMH parameters and measurement definitions are in `docs/benchmarks/methodology.md`; raw output is in `docs/benchmarks/`.
- Results: JMH 5,000-zone R-tree throughput at 8 threads was 8,091,255 queries/s (16 vertices) and 2,923,697 queries/s (500 vertices). The allocation probe measured 0.00077 and 0.00216 B/op respectively (effectively profiler resolution after warmup). Corrected `forEachCandidate` JMH measured 19,359,288 and 16,778,052 ops/s. Build AverageTime measured 2.679/2.759 ms and SingleShotTime 5.900/5.339 ms for 16/500 vertices. Runtime heap-delta sweep measured 7,279,272 B (5k × 16), 24,418,992 B (20k × 16), 122,581,096 B (100k × 16), and 120,986,544 B (5k × 500); this Runtime full-GC method is approximate and process-sensitive.
- Open-loop results: both 60-second workloads scheduled/completed 3,000,000 point queries at 50,000 queries/s with zero drops and worker failures. Baseline query-service p50/p99: 0.833/9.215 μs; snapshot rebuild/swap every two seconds: 0.833/4.127 μs. Scheduled-deadline-to-completion p50/p99 was 8.791/20.719 μs baseline and 8.751/20.383 μs during swaps. Rebuild mode published 30 snapshots. These are point queries only; HTTP admission and durable ping processing are not measured.
